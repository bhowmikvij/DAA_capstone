# Courier Route & Packing Optimizer
**DAA Capstone Project | Bhowmik Vij | Roll No. 2501010195**

A Python prototype that prioritizes parcels, selects a feasible delivery load, calculates shortest paths, and builds an approximate multi-stop delivery tour.

## Features
- **Merge Sort:** orders parcels by higher priority, then earlier deadline.
- **0/1 Knapsack (Dynamic Programming):** maximizes parcel value within vehicle weight capacity.
- **Dijkstra:** computes shortest paths in a weighted road graph.
- **Nearest-Neighbor TSP approximation:** creates an ordered delivery tour from the depot and selected customers.
- **Performance study:** compares Merge Sort with Python's built-in sort and measures knapsack, Dijkstra, and route-planning runtimes on increasing input sizes.

## Data format
- `parcels.csv`: `parcel_id,customer_id,weight,deadline_hours,priority,value`
- `roads.csv`: `from,to,distance`

Road distances are positive weights. The graph is undirected. Depot ID is `DEPOT`; customer IDs must exist in the road network.

## Algorithms and complexity
| Component | Technique | Time complexity |
|---|---|---|
| Parcel ordering | Merge Sort | O(n log n) |
| Packing | 0/1 Knapsack DP | O(nW), W = integer capacity |
| Single-source shortest paths | Dijkstra with adjacency list and linear minimum selection | O(V² + E) |
| Delivery tour | Nearest Neighbor with Dijkstra per selected leg | O(k(V² + E) + k²) in this implementation |
| Benchmarking | Repeated timed runs | Depends on input sizes |

Dijkstra uses a linear minimum search to keep the algorithm easy to understand in a DAA viva. A heap-based implementation can improve sparse-graph performance.

## Assumptions and limitations
1. Parcel weight and vehicle capacity are positive integers in the same unit (sample data uses kg).
2. Parcel value is a simulated business value used as the knapsack objective.
3. Deadline and priority are used for sorting; deadlines are not enforced as delivery time windows.
4. Knapsack maximizes total value within capacity; it does not guarantee every urgent parcel is selected.
5. Nearest Neighbor is a heuristic, not a guaranteed optimal TSP solution.
6. The road graph is a simulation, not live map or traffic data.
